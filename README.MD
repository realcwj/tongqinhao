# 通琴号 · 跨境通勤助手

**本项目使用 AI 协助编写**

横琴 ⇄ 澳门跨境通勤班次查询网页应用。根据你的位置或手动选择，快速找到最近的上车站点，掌握后续班次与车辆状态。

🔗 **在线使用**：<https://realcwj.github.io/tongqinhao/>

📦 **项目仓库**：<https://github.com/realcwj/tongqinhao>

---

## ✨ 功能特性

- **自动定位**：打开页面自动申请定位，判断你当前在横琴还是澳门，并推荐附近最近的上车站点（距离范围与数量见 `config.js`）。
- **快速选择**：一键直达常用线路，例如「琴澳大学城 → 澳大」「澳大 → 琴澳大学城」，自动设置区域、上车站点与下车站点并跳转班次结果；另有「附近 → 澳大」「附近 → 琴澳大学城」，按定位自动选中附近最近的上车站点。
- **双向跨境规则**：横琴上车只能前往澳门下车，澳门上车只能前往横琴下车，站点推荐按线路方向自动过滤。
- **口岸站上车**：双向线路驶入对方区域后的首站（横琴口岸两侧）同样可上车，可在该侧后续站点下车，适合口岸短途接驳。
- **多选站点**：可同时选择多个上车站点 / 下车站点，合并查询所有相关班次并去重。
- **站点时间轴**：每个班次可展开完整站点时刻，标记上车点与可下车点。
- **车辆状态**：未发车、在某站、两站之间、已到终点等实时状态展示。
- **全部线路页**：浏览全部跨境线路，支持关键词搜索与方向筛选，展开查看完整站点时刻。

## 🖥 页面说明

| 页面 | 说明 |
| --- | --- |
| `index.html` | 通勤助手主页：定位 → 快速选择 → 我当前在 → 附近站点 → 选择上/下车站 → 后续班次 |
| `routes.html` | 全部跨境线路目录：搜索、筛选、展开线路站点时刻 |

## 📦 项目结构

```
├── .github/workflows/  # 定时任务：每天北京时间 02:00 自动更新线路数据
├── index.html          # 通勤助手主页
├── routes.html         # 全部跨境线路页
├── config.js           # 全站配置：数据同步日期/链接、数据源、附近范围与条数等参数
├── app-v2.js           # 主页逻辑（定位、选择、班次查询）
├── routes.js           # 线路页逻辑
├── styles.css          # 全局样式
├── processed.json      # 前端唯一业务数据源（每日自动更新）
├── get_all_route.py    # 数据抓取与整理脚本（由 GitHub Actions 每天自动执行）
└── json/               # 抓取原始 JSON 快照（仅本地生成，不提交仓库）
```

## 🔄 数据自动更新

`processed.json` 由 `get_all_route.py` 抓取通琴号接口生成，并由 `.github/workflows/update-routes.yml` 每天**北京时间 02:00**（UTC 18:00）自动执行一次，随后把变更提交回仓库；也可以在 GitHub 的 Actions 页面手动触发（`workflow_dispatch`）。

每次运行会重新抓取全部线路，并按发车班次整理数据：

| 字段 | 说明 |
| --- | --- |
| `id` | 原线路 ID（同一线路的多个班次共用一个 ID） |
| `uid` | 班次唯一标识，格式 `线路ID@发车时间`，前端据此区分同线路的不同班次 |
| `departure` | 该班次的发车时间（`HH:MM`） |
| `dates` | 该班次未来几天的开行日期（`YYYY-MM-DD`，取自发车时间接口） |
| `has_schedule` | 未来几天是否有发车计划；`false` 表示暂无发车计划（此时 `departure` 为 `null`、`dates` 为空） |
| `route_name` | 线路名称（保持接口原名） |
| `bus_id` | 车辆/线路业务标识 |
| `stops` | 该班次各站点的时刻与坐标（站点接口只返回当前班次，脚本按发车时间整体平移得到各班次时刻） |

若发车时间接口未返回任何发车时间，说明该线路未来几天没有发车计划，脚本会输出 `has_schedule: false` 的条目（不再用站点时刻兜底成班次），总览页显示「暂无发车计划」，也不会出现在「后续班次」查询结果中。

运行结束后还会把 `config.js` 中的 `DATA_SYNC_DATE` 更新为运行当天（北京时间），页面顶部「数据同步」胶囊随之更新。`json/` 目录中的接口原始快照只在运行环境本地生成，不提交仓库。

> **本地维护提示（重要）**：云端提交**不会**自动同步到你本地，Git 不是文件同步工具。开始任何本地改动（尤其跑脚本、改前端）前先拉一次：
>
> ```bash
> git pull
> ```
>
> 忘了拉取时，提交本身不会报冲突，但 `git push` 会因非快进（`! [rejected] ... fetch first`）而被拒——先 `git pull` 即可（此时远端只多了自动数据提交，是快进合并，不会有冲突）。
> 只有在「本地已提交过数据文件 + 远端同时也有新的自动提交」时才会出现 `processed.json`/`config.js` 的**内容冲突**；此时不要手工合并数据文件，直接重新跑 `python get_all_route.py` 生成最新数据再提交即可（定时任务侧已用 `-X theirs` 自动以新抓取数据为准）。

本地手动运行（需要能访问通琴号接口）：

```bash
python get_all_route.py
```
